# NanoASR

[English](README.md) · **Русский**

Оффлайн-сервер распознавания речи на [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx).
Один бинарь, инференс на CPU, пословные тайминги, три диалекта HTTP API и встроенный
веб-интерфейс.

Сервис рассчитан на пакетную обработку файлов: записи разговоров, интервью, совещаний
длиной от одной минуты до получаса, моно и стерео, включая телефонные 8 кГц. Ни один
байт аудио не покидает машину — модели работают локально, сетевой доступ нужен только
для первичной загрузки весов.

## Архитектура

Запрос проходит фиксированный конвейер. Каждый этап измеряется отдельно и попадает в
`stats.stages_ms` ответа.

```
                                  ┌──────────────┐
файл ──► decode ──► vad ──► asr ──►   assemble   ──► diarize ──► post ──► результат
         │          │       │      │              │   │           │
    ffmpeg или  Silero  sherpa-onnx  токены     pyannote +    пунктуация,
    нативный    VAD v5  батчами по   в слова    эмбеддинги    ITN, hotwords
    WAV/PCM             сегментам    с таймингами
```

| Этап | Назначение |
|---|---|
| `decode` | Определение формата, декодирование, приведение к 16 кГц, обработка каналов |
| `vad` | Разбиение на сегменты речи, вычисление зон тишины |
| `asr` | Распознавание сегментов батчами под управлением CPU-губернатора |
| `assemble` | Сборка токенов в слова с границами по времени |
| `diarize` | Определение говорящих и нарезка сегментов по границам реплик |
| `post` | Пунктуация, инверсная нормализация текста |

Ключевые свойства реализации:

- **Единая точка входа.** Вся бизнес-логика находится за интерфейсом `core.Service`.
  Диалекты API преобразуют формы запроса и ответа и не имеют доступа к пулу моделей,
  реестру или очереди. Добавление диалекта — один пакет, регистрирующий себя в `init()`.
- **Пул моделей.** Резидентные экземпляры с подсчётом ссылок, вытеснением по LRU и
  горячей заменой ревизии без разрыва выполняющихся запросов.
- **CPU-губернатор.** Число одновременно исполняемых батчей ограничено взвешенным
  семафором, чтобы параллельные запросы не деградировали до нуля пропускной способности.
- **Очередь задач.** SQLite (чистый Go, без cgo) для метаданных, файловый спул для
  аудио, приоритеты, возобновление после рестарта, поток событий по SSE, вебхуки с
  подписью HMAC.
- **Один артефакт.** Веб-интерфейс встраивается в бинарь на этапе компиляции.

## Возможности

**Распознавание**

- Пословные тайминги с достоверностью для каждого слова.
- Семейства моделей: `nemo_ctc`, `zipformer_ctc`, `wenet_ctc`, `transducer`, `telespeech`.
- Батчинг сегментов с ограничением по числу и суммарной длительности.
- Выбор модели на запрос; параллельная резидентность нескольких моделей.
- Методы декодирования `greedy_search` и `modified_beam_search`.
- Смещение распознавания в пользу заданных слов (hotwords).

**Аудио**

- WAV и сырой PCM декодируются в процессе, без внешних зависимостей: 16/24/32 бита,
  float32, a-law и µ-law.
- Все остальные форматы — через ffmpeg, который остаётся опциональным.
- Полифазный ресемплер до 16 кГц.
- Три режима обработки каналов: сведение, первый канал, раздельное распознавание.

**Результат**

- Текст, сегменты, слова, зоны тишины, говорящие, доля речи, статистика по этапам.
- Форматы ответа: JSON, обычный текст, SRT, VTT, TSV.
- Субтитры с метками говорящих.

**Постобработка**

- Пунктуация и регистр: от модели распознавания либо отдельной моделью пунктуации.
- Инверсная нормализация текста для русского языка: числа, даты, время, деньги,
  телефоны, проценты.
- Диаризация: определение говорящих, пословная привязка, нарезка сегментов по репликам.

**Эксплуатация**

- Три диалекта HTTP API одновременно на одном порту.
- Аутентификация по ключам API с ограничением частоты запросов и приоритетами.
- Реестр моделей: встроенный каталог, загрузка с проверкой SHA-256, управление через API.
- Автоматический подбор размеров пулов по числу ядер и объёму памяти.
- Проверки `/healthz` и `/readyz`, отражающие глубину очереди.

## Установка

### Готовые сборки

Архивы публикуются на [странице релизов](https://github.com/usunrise88/NanoASR/releases).

| Файл | Платформа |
|---|---|
| `nanoasr-<tag>-linux-amd64.tar.gz` | Linux, веб-интерфейс включён |
| `nanoasr-<tag>-linux-amd64-noui.tar.gz` | Linux, без веб-интерфейса |
| `nanoasr-<tag>-windows-amd64.zip` | Windows, веб-интерфейс включён |
| `nanoasr-<tag>-windows-amd64-noui.zip` | Windows, без веб-интерфейса |

Веб-интерфейс встраивается на этапе компиляции, поэтому сборка без него — отдельный
бинарь, а не флаг запуска.

Нативные библиотеки (`libonnxruntime`, `libsherpa-onnx`) находятся внутри архива.
Архив следует распаковывать целиком: в Linux `RUNPATH` бинаря указывает на `./lib`,
в Windows загрузчик ищет DLL рядом с исполняемым файлом.

```bash
tar -xzf nanoasr-v1.0.0-linux-amd64.tar.gz -C ~/nanoasr
cd ~/nanoasr
```

### Служба systemd

Файл `nanoasr.service` входит в состав Linux-архива. Разметка каталогов: бинарь и
конфигурация в `/opt/nanoasr`, модели, база задач и спул — в `/var/lib/nanoasr`.

```bash
sudo useradd -r -s /usr/sbin/nologin nanoasr
sudo mkdir -p /opt/nanoasr /var/lib/nanoasr
sudo tar -xzf nanoasr-v1.0.1-linux-amd64.tar.gz -C /opt/nanoasr
sudo chown -R nanoasr:nanoasr /opt/nanoasr /var/lib/nanoasr
```

Конфигурация, ключи и модели создаются от имени служебного пользователя, чтобы
загруженные файлы принадлежали ему:

```bash
sudo -u nanoasr /opt/nanoasr/nanoasr init \
  -config /opt/nanoasr/nanoasr.yaml \
  -data-dir /var/lib/nanoasr \
  -addr 127.0.0.1:8080 \
  -force
```

`-force` требуется потому, что архив уже содержит `nanoasr.yaml`. Оба выпущенных ключа
выводятся на экран; они же остаются в конфигурации.

```bash
sudo cp /opt/nanoasr/nanoasr.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now nanoasr
systemctl status nanoasr
```

Юнит запускает `nanoasr serve -config /opt/nanoasr/nanoasr.yaml` и применяет
`ProtectSystem=strict`: единственный каталог, доступный службе на запись, —
`/var/lib/nanoasr`. Конфигурация читается при старте, поэтому выпуск и отзыв ключей
требуют `systemctl restart nanoasr`.

Готовность проверяется по `/readyz`, а не по факту запуска процесса: загрузка весов
занимает секунды, а при заполненной очереди `/readyz` отвечает `503`. Причина отказа
запуска выводится в журнал:

```bash
journalctl -u nanoasr -n 50 --no-pager
```

### Docker

```bash
docker compose -f deploy/docker-compose.yml up --build
```

Образ содержит ffmpeg и нативные библиотеки. Веса моделей хранятся в томе
`/var/lib/nanoasr` и не попадают в образ. Ключ API задаётся переменной окружения:

```bash
NANOASR_AUTH_KEYS=sk-... docker compose -f deploy/docker-compose.yml up -d
```

### Сборка из исходников

Требуется Go 1.24+, компилятор C/C++ (cgo обязателен — sherpa-onnx написан на C++) и
Node 22+ для сборки веб-интерфейса.

```bash
make web build        # веб-интерфейс и сервер
make build-noui       # сервер без веб-интерфейса
make dist             # переносимый архив с библиотеками
make docker           # образ контейнера
```

ffmpeg опционален. Без него доступны WAV и PCM, включая a-law и µ-law; остальные
форматы отклоняются с кодом `415`.

### Обновление

Веса моделей, база задач и спул лежат в каталоге данных и переживают обновление любым
из способов. Версию после обновления показывает `nanoasr version` и ответ `/healthz`.

**Архив и systemd.** Архив содержит собственный `nanoasr.yaml`, поэтому распаковка
поверх каталога перезаписала бы рабочую конфигурацию — её нужно исключить:

```bash
sudo systemctl stop nanoasr
sudo tar -xzf nanoasr-<новая версия>-linux-amd64.tar.gz -C /opt/nanoasr \
  --exclude=./nanoasr.yaml
sudo chown -R nanoasr:nanoasr /opt/nanoasr
sudo systemctl start nanoasr
```

Если в новой версии изменился файл юнита, его следует скопировать заново и выполнить
`systemctl daemon-reload`. Смена варианта сборки — с веб-интерфейсом или без — это то же
обновление: меняется только бинарь.

**Архив без systemd, включая Windows.** Остановить процесс, распаковать архив поверх
каталога, сохранив свою конфигурацию, запустить снова. В Windows следует заменить
`nanoasr.exe` и файлы `*.dll` вместе — библиотеки и бинарь версионируются совместно.

**Docker.** Пересборка образа с сохранением тома данных:

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

Том `nanoasr-data` не пересоздаётся, поэтому веса моделей заново не загружаются.

**Сборка из исходников.**

```bash
git pull
make web build
```

Затем перезапустить процесс или службу. Если сервер установлен из архива, собранный
бинарь заменяется тем же способом, что и при обновлении из релиза.

## Быстрый старт

### Команда `init`

`nanoasr init` формирует рабочую конфигурацию, выпускает два ключа API и загружает
модели по умолчанию.

```bash
./nanoasr init
./nanoasr serve -config nanoasr.yaml
```

```
configuration  nanoasr.yaml
data           /var/lib/nanoasr

admin key      sk-nanoasr-...
user  key      sk-nanoasr-...
```

Каталог данных — `/var/lib/nanoasr`, если он доступен для записи, иначе
`./nanoasr-data`. Выбранный путь выводится на экран.

| Флаг | Назначение |
|---|---|
| `-config FILE` | Путь к создаваемой конфигурации, по умолчанию `nanoasr.yaml` |
| `-data-dir DIR` | Каталог моделей и базы данных |
| `-addr ADDR` | Адрес прослушивания, по умолчанию `127.0.0.1:8080` |
| `-model ID` | Модель распознавания по умолчанию |
| `-no-diarize` | Не загружать модели диаризации |
| `-no-download` | Только создать конфигурацию |
| `-force` | Перезаписать существующий файл конфигурации |

Конфигурация записывается и проверяется загрузчиком до начала скачивания весов, что
исключает появление файла, который сервер откажется читать.

### Ключи API

```bash
nanoasr key list                            # перечень ключей, секреты маскируются
nanoasr key issue ci -rps 5                 # выпуск ключа, секрет выводится в stdout
nanoasr key issue bot -hash                 # в конфигурацию попадает только sha256
nanoasr key issue ops -admin -interactive   # административный ключ вне общей очереди
nanoasr key remove ci                       # отзыв ключа
```

| Флаг | Назначение |
|---|---|
| `-admin` | Доступ к управлению моделями и конфигурацией |
| `-interactive` | Задачи ключа обслуживаются вне пакетной очереди |
| `-rps N` | Ограничение частоты запросов, `0` — без ограничения |
| `-hash` | Хранить только SHA-256; секрет выводится один раз |

Конфигурация редактируется как YAML-документ: комментарии, порядок ключей и
отсутствующие параметры сохраняются. Запись атомарна, результат проверяется до замены
файла. Ключи считываются при запуске, поэтому изменения применяются после перезапуска
сервера.

Режим `auth.mode: open` допускается только при прослушивании адреса обратной петли.
Режим `apikey` с пустым списком ключей приводит к отказу в запуске.

## Веб-интерфейс

Одностраничное приложение доступно на `/ui/` и включается параметром `ui.enabled`.
Ключ API запрашивается интерфейсом при первом ответе `401`.

| Раздел | Назначение |
|---|---|
| Распознавание | Загрузка файла, выбор модели и параметров, отслеживание прогресса |
| Результат | Плеер с подсветкой слова, фильтр по говорящему, поиск, экспорт |
| Задачи | История, статусы, фильтры, отмена, повторный просмотр результата |
| Модели | Каталог, загрузка весов, резидентность, закрепление, горячая замена |
| Настройки | Действующая конфигурация сервера в режиме чтения |

Интерфейс полностью работает поверх публичного API и не имеет собственных endpoint'ов.

## Поддерживаемые API

Диалекты включаются в конфигурации и обслуживаются одновременно:

```yaml
api:
  dialects: [openai, native, era]
```

### `native` — полный интерфейс сервиса

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/transcribe` | Синхронное распознавание |
| `POST` | `/api/v1/jobs` | Постановка задачи в очередь |
| `GET` | `/api/v1/jobs` | История с курсорной пагинацией |
| `GET` | `/api/v1/jobs/{id}` | Состояние и результат задачи |
| `GET` | `/api/v1/jobs/{id}/events` | Поток событий SSE |
| `DELETE` | `/api/v1/jobs/{id}` | Отмена задачи |
| `GET` | `/api/v1/models` | Резидентные и установленные модели |
| `GET` | `/api/v1/catalog` | Встроенный каталог моделей |
| `POST` | `/api/v1/models/{id}/download` | Загрузка весов, прогресс по SSE |
| `POST` | `/api/v1/models/{id}/load` | Загрузка модели в память |
| `POST` | `/api/v1/models/{id}/unload` | Выгрузка модели |
| `POST` | `/api/v1/models/{id}/pin` | Защита от вытеснения по LRU |
| `POST` | `/api/v1/models/{id}/reload` | Горячая замена ревизии |
| `GET` | `/api/v1/config` | Действующая конфигурация |

Управление моделями и конфигурацией требует административного ключа. Ошибки
возвращаются в формате RFC 9457 `application/problem+json`.

Параметры запроса: `model`, `language`, `response_format`, `channel_mode`,
`decoding_method`, `max_active_paths`, `diarize`, `num_speakers`, `punctuate`, `itn`,
`hotwords[]`, `hotwords_score`, `strict`, `webhook_url`.

Форматы ответа: `json`, `text`, `srt`, `vtt`.

### `openai` — совместимость с OpenAI Audio API

| Метод | Путь |
|---|---|
| `POST` | `/v1/audio/transcriptions` |
| `POST` | `/v1/audio/translations` |
| `GET` | `/v1/models` |
| `GET` | `/v1/models/{id}` |

Поддерживаются `file`, `model`, `language`, `prompt`, `response_format`,
`timestamp_granularities[]`. Форматы ответа: `json`, `verbose_json`, `text`, `srt`,
`vtt`. Ответ `verbose_json` дополнен полями `timestamp_source`, `silence`, `warnings`
и `stats`; клиенты OpenAI игнорируют неизвестные поля.

Отличия от оригинального API:

- `/v1/audio/translations` возвращает `501`: модели перевода не поставляются.
- `prompt` интерпретируется как список hotwords через запятую, а не как подсказка
  языковой модели.
- `temperature` принимается и не влияет на результат: декодеры не выполняют сэмплирование.

### `era` — совместимость с whisper-asr-webservice

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/asr` | Синхронное распознавание, ответ файлом |
| `POST` | `/detect-language` | Определение языка |
| `POST` | `/asr_task` | Постановка задачи, возврат идентификатора |
| `GET` | `/asr_task/{task_id}` | Опрос состояния и получение результата |

Файл передаётся в поле `audio_file`, остальные параметры — в строке запроса: `encode`,
`task`, `language`, `initial_prompt`, `vad_filter`, `word_timestamps`, `diarize`,
`min_speakers`, `max_speakers`, `output`.

Форматы `output`: `txt` (по умолчанию), `vtt`, `srt`, `tsv`, `json`. Все передаются с
типом `text/plain` и заголовками `Asr-Engine` и `Content-Disposition`.

Тела ответов повторяют эталонный сервис, а не нативный результат: `txt` — строка на
сегмент, `tsv` — без строки заголовка, `json` —
`{"segments": [{"start", "end", "text", "words": [{"word", "start", "end", "score"}]}],
"word_segments": [...], "language": "..."}`. Слова присутствуют всегда, независимо от
`word_timestamps`. Модели, не сообщающие достоверность по словам, дают `score` равный 0
и предупреждение `word_confidence_unavailable`.

Отличия от оригинального сервиса:

| Параметр или поведение | Реализация в NanoASR |
|---|---|
| `task=translate` | `501`, модели перевода не поставляются |
| `initial_prompt` | Список hotwords через запятую |
| `encode`, `vad_filter` | Принимаются, не влияют на результат: задаются конфигурацией сервера |
| `min_speakers`, `max_speakers` | Сводятся к точному числу говорящих; диапазон отбрасывается |
| `task_id` | Идентификатор задачи с суффиксом запрошенного формата |
| `GET /` | Не обслуживается: перенаправление на `/docs` не реализовано |
| Аутентификация | Обязательна, как и для остальных диалектов |

Поля для предупреждений в этом контракте отсутствуют, поэтому сведения о применённых
ограничениях передаются в заголовке `X-NanoASR-Warnings` в виде списка кодов.

`/detect-language` возвращает язык, объявленный разрешившейся моделью распознавания.
Поле `confidence` равно `1`, если модель поддерживает единственный язык, и `0`, если
языков несколько и выбран первый. Модель идентификации языка в поставку не входит.

## Настройки распознавания

### `channel_mode` — обработка каналов

| Значение | Поведение |
|---|---|
| `downmix` (по умолчанию) | Каналы усредняются в одну дорожку |
| `first` | Используется нулевой канал, остальные отбрасываются |
| `split` | Каждый канал распознаётся отдельно, результаты объединяются по времени |

`split` предназначен для стереозаписей, в которых собеседники разведены по каналам
(телефонная запись A/B leg). Каждый сегмент и каждое слово содержат поле `channel`,
что даёт разделение говорящих без диаризации и точнее её. Диаризация при `split` не
выполняется и возвращает предупреждение `diarization_skipped_split`.

`first` отбрасывает остальные каналы полностью и применим, когда второй канал заведомо
не содержит речи.

В режиме `split` каждый канал декодируется целиком, поэтому объём памяти умножается на
число каналов. Верхняя граница задаётся параметром `audio.max_split_channels`
(по умолчанию 2); файл с бо́льшим числом каналов отклоняется с кодом `400`.

### `decoding_method` — метод декодирования

| | `greedy_search` | `modified_beam_search` |
|---|---|---|
| Семейства моделей | Все | Только `transducer` |
| Принцип | На каждом шаге выбирается наиболее вероятный токен | Параллельно рассматривается `max_active_paths` гипотез |
| Относительная стоимость | Базовая | +29 % при 4 путях, +57 % при 8 путях |
| Поддержка hotwords | Нет | Требуется |

`greedy_search` применяется по умолчанию. `modified_beam_search` повышает точность на
записях с шумом, узкополосным каналом и редкими именами собственными; на чистом
материале разница в тексте может отсутствовать.

Модели CTC перебор гипотез не поддерживают. Запрос `modified_beam_search` к такой
модели обслуживается штатным методом и сопровождается предупреждением
`decoding_method_unavailable`.

`decoding_method` и `max_active_paths` фиксируются при загрузке распознавателя, поэтому
их изменение на уровне запроса требует второго резидентного экземпляра модели. Бюджет
задаётся параметром `asr.variants.max`; при нулевом значении запрос обслуживается
настройками модели с соответствующим предупреждением.

### `hotwords` — смещение распознавания

Список слов и фраз, вероятность которых повышается при декодировании: имена
собственные, названия организаций, терминология. Механизм изменяет вероятности, а не
словарь: слово из списка может не появиться в результате либо появиться ошибочно.

Условия применения:

1. Семейство модели — `transducer`.
2. `decoding_method: modified_beam_search`.
3. Единица моделирования допускает токенизацию фразы: `cjkchar` — без дополнительных
   файлов, `bpe` и `cjkchar+bpe` — при наличии `bpe_vocab` в манифесте модели.

Рекомендуемый объём списка — десятки фраз. Ограничение определяется точностью, а не
производительностью: чем длиннее список, тем чаще смещение срабатывает на неверных
позициях. В список следует включать только те фразы, которые модель действительно
распознаёт неверно.

Список входит в ключ пула моделей: каждый уникальный набор hotwords требует отдельного
резидентного экземпляра. Механизм предназначен для стабильного словаря, а не для
параметра, изменяющегося от запроса к запросу.

```yaml
asr:
  variants:
    max: 1
    allow_hotwords: true
postproc:
  hotwords:
    enabled: true
    default_score: 1.5
```

`hotwords_score` определяет силу смещения; рабочий диапазон — 1.5–2.0. В диалекте
OpenAI список передаётся через `prompt` без значения, и применяется
`postproc.hotwords.default_score`.

Модели встроенного каталога перечисленным условиям не удовлетворяют: русские модели
используют `char` либо подслова без словаря. Для работы механизма требуется запись
каталога с файлом `bpe_vocab`.

## Диаризация

Диаризация выполняется вторым проходом по всей записи: модель сегментации определяет
границы реплик, модель эмбеддингов преобразует фрагменты в векторы голоса,
кластеризация объединяет фрагменты одного говорящего.

Результат содержит поля `speaker` и `speaker_confidence` на уровне слов и сегментов,
а также сводку `speakers[]` с длительностью речи и числом сегментов. Сегменты
разрезаются по границам реплик, короткие фрагменты поглощаются соседними.

```yaml
diarization:
  enabled: true
  segmentation_model: pyannote-segmentation-3
  embedding_model: campplus-sv-voxceleb
  clustering:
    num_clusters: 0
    threshold: 0.4
  min_duration_on: 0.3
  min_duration_off: 0.5
```

| Параметр | Назначение |
|---|---|
| `segmentation_model` | Модель определения границ реплик |
| `embedding_model` | Модель векторного представления голоса |
| `clustering.num_clusters` | Фиксированное число говорящих; `0` — кластеризация по порогу |
| `clustering.threshold` | Порог косинусного расстояния при неизвестном числе говорящих |
| `min_duration_on` | Минимальная длительность реплики, с |
| `min_duration_off` | Минимальная длительность паузы между репликами, с |

Параметр запроса `num_speakers` задаёт число говорящих для конкретного файла.
Он не гарантирует получение указанного числа: кластеризация строит дендрограмму
методом полной связи и выполняет разрез либо по высоте (`threshold`), либо по
заданному числу листьев. При наличии выброса разрез по числу листьев может отделить
именно его. Если разделено меньше говорящих, чем запрошено, ответ содержит
предупреждение `diarization_fewer_speakers`.

**Выбор модели эмбеддингов** определяет качество разделения. Модель
`campplus-sv-zh-en` обучена на китайском и английском материале и на близких русских
голосах формирует единственный кластер при любом пороге. Модель по умолчанию —
`campplus-sv-voxceleb`, обученная на многоязычном корпусе VoxCeleb. Для голосов с
высоким сходством применяется `wespeaker-voxceleb-resnet34`, вдвое более
требовательная к процессору.

Если все реплики отнесены к одному говорящему, применяются следующие меры в порядке
убывания эффективности:

1. Использовать `channel_mode: split`, если говорящие разведены по каналам.
2. Заменить модель эмбеддингов на `wespeaker-voxceleb-resnet34`.
3. Понизить `clustering.threshold` до 0.35.
4. Задать `num_speakers`, если число говорящих известно точно.

Частота дискретизации моделей диаризации сверяется с `audio.target_sample_rate` при
запуске; расхождение приводит к отказу в запуске.

## Примеры запросов

Далее `KEY` — ключ API, выпущенный командой `nanoasr init` или `nanoasr key issue`.

**Синхронное распознавание**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/api/v1/transcribe \
  -F file=@call.wav
```

**Пословные тайминги и статистика**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/api/v1/transcribe \
  -F file=@call.wav \
  | jq '{text, rtf: .stats.rtf, stages: .stats.stages_ms, words: .segments[0].words[:3]}'
```

**Диаризация с известным числом говорящих**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/api/v1/transcribe \
  -F file=@call.wav -F diarize=true -F num_speakers=2 \
  | jq '.speakers, [.segments[] | {start, end, speaker}]'
```

**Стерео с разделением по каналам**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/api/v1/transcribe \
  -F file=@call.wav -F channel_mode=split \
  | jq '[.segments[] | {channel, start, text}]'
```

**Субтитры**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/api/v1/transcribe \
  -F file=@call.wav -F diarize=true -F response_format=srt \
  -o call.srt
```

**Асинхронная задача с отслеживанием прогресса**

```bash
JOB=$(curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/api/v1/jobs \
  -F file=@meeting.wav -F diarize=true -F itn=true | jq -r .id)

curl -s -N -H "Authorization: Bearer $KEY" \
  "http://localhost:8080/api/v1/jobs/$JOB/events"

curl -s -H "Authorization: Bearer $KEY" \
  "http://localhost:8080/api/v1/jobs/$JOB" | jq .result.text
```

**Уведомление по вебхуку**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/api/v1/jobs \
  -F file=@call.wav \
  -F webhook_url=https://example.com/nanoasr
```

**Диалект OpenAI**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST http://localhost:8080/v1/audio/transcriptions \
  -F file=@call.wav -F response_format=verbose_json \
  | jq '.text, .words[:3]'
```

**Диалект era**

```bash
curl -s -H "Authorization: Bearer $KEY" \
  -X POST "http://localhost:8080/asr?output=srt&diarize=true&min_speakers=2&max_speakers=2" \
  -F audio_file=@call.wav

TASK=$(curl -s -H "Authorization: Bearer $KEY" \
  -X POST "http://localhost:8080/asr_task?output=json&word_timestamps=true" \
  -F audio_file=@call.wav | jq -r .task_id)

curl -s -H "Authorization: Bearer $KEY" "http://localhost:8080/asr_task/$TASK"
```

**Состояние сервера**

```bash
curl -s http://localhost:8080/healthz
curl -s http://localhost:8080/readyz
```

## Реестр моделей

Веса моделей не входят в поставку и загружаются на целевую машину. Каждая запись
каталога закреплена по URL, размеру и контрольной сумме SHA-256; загруженные файлы
проверяются перед использованием.

```bash
nanoasr models catalog                       # доступные записи каталога
nanoasr models list                          # установленные модели
nanoasr models pull gigaam-v3-ctc-punct-ru   # загрузка
nanoasr models inspect ./my-model --probe sample.wav
```

`models inspect` определяет семейство и словарь модели, извлекает метаданные из файлов
`.onnx` и формирует черновик манифеста для добавления модели в реестр. Флаг `--probe`
проверяет каждое значение `features.dim` в отдельном процессе.

Модели загружаются в память по требованию, вытесняются по LRU и подлежат горячей замене.
Одновременная резидентность ограничивается параметрами `asr.max_resident_models` и
`asr.max_model_rss_mb`.

### Модели по умолчанию

`nanoasr init` загружает четыре модели, достаточные для полного цикла обработки
русской речи:

| Идентификатор | Назначение | Размер |
|---|---|---|
| `gigaam-v3-ctc-punct-ru` | Распознавание, русский, со знаками препинания и регистром | 163 МБ |
| `silero-vad-v5` | Определение речевой активности | 0,6 МБ |
| `pyannote-segmentation-3` | Сегментация говорящих | 7 МБ |
| `campplus-sv-voxceleb` | Эмбеддинги говорящих | 30 МБ |

Модель распознавания по умолчанию расставляет знаки препинания и заглавные буквы
самостоятельно, поэтому отдельная модель пунктуации для русского языка не требуется.
